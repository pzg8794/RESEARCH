# Application Session Control

Last operational review: 2026-09-09

Purpose: prevent job, fellowship, and PhD application work from becoming disconnected across email, portals, calendars, and Git.

## Non-negotiable session rule

Every application work session must begin and end with this sequence:

1. Read the nearest verified deadlines and overdue checkpoints.
2. Reconcile the job queue, PhD queue, Fulbright/fellowship queue, and relevant UofR/RIT mailboxes.
3. Work in deadline order unless a blocking dependency makes another item immediately actionable.
4. Record every state change as `SAVED`, `PREPARED`, `SUBMITTED`, `WAITING`, `BLOCKED`, or `CLOSED`.
5. Require live portal/email evidence before claiming submission, receipt, rejection, interview, or completion.
6. Add the Git work-package link to each evidence-backed calendar follow-up.
7. Commit and push only the documentation and artifacts created for the completed action.
8. End by stating the next deadline, next action, owner, and evidence gap.

Calendar dates, old checkboxes, and draft files do not prove completion.

## End-of-session handoff format

For every unfinished item, leave:

`ITEM — STATUS — VERIFIED DEADLINE — NEXT ACTION — OWNER — EVIDENCE LINK — FOLLOW-UP DATE`

If a deadline or status has not been checked against a current primary source, label it `UNVERIFIED`; do not present it as current merely because it appears in Git.
